# 33 - Shopify Orders API Landing MVP

## Summary

This milestone added the first Shopify Admin API landing path for order data.

The goal was to land Shopify API-derived orders and order line items into isolated BigQuery `raw_load` tables without replacing the existing CSV ingestion pipeline, modifying canonical `raw.shopify_*` tables, or changing downstream staging, marts, or analysis logic.

The milestone succeeded.

## What changed

Added a new Airflow DAG:

```text
dags/mm_shopify_api_orders_landing_mvp.py
```

This DAG:

- checks local output folder write access before starting an API job
- starts a Shopify Bulk Operation for orders and line items
- polls until the Bulk Operation completes
- downloads the JSONL result locally
- separates `Order` and `LineItem` records
- loads orders into `raw_load.shopify_orders_api_latest`
- loads line items into `raw_load.shopify_order_line_items_api_latest`
- validates the API landing tables
- writes a local landing summary

Added a validation query:

```text
sql/validation/shopify_api_orders_landing_validation.sql
```

## Review findings

The orders API landing path is structurally sound:

- order landing table populated
- line item landing table populated
- no duplicate order GraphQL IDs
- no duplicate line item GraphQL IDs
- no missing order numbers
- no line items missing parent order IDs
- no orphaned line items

The API extract returned orders from March 1, 2026 through April 30, 2026.

Of the 626 API orders, 578 matched the existing CSV-derived warehouse by order number. The 48 API-only orders were reviewed and found to be newer orders from April 22 through April 30, which likely appeared after the latest CSV export.

## Design decisions

This milestone is landing-only.

It intentionally does not:

- replace Shopify CSV ingestion
- modify canonical `raw.shopify_orders`
- modify `staging.stg_shopify_orders`
- modify `staging.stg_shopify_order_items`
- modify `marts.fct_orders`
- modify `marts.fct_order_items`
- modify business-facing analysis models
- schedule API ingestion
- use API order data as the warehouse source of truth

The existing CSV ingestion path remains the known-good historical baseline.

For forward scheduled ingestion, full historical order API access is not required as long as the project defines a cutover date and runs API ingestion frequently enough to stay within the accessible order window.

Current migration path:

```text
Shopify API -> isolated API landing tables -> API-vs-CSV reconciliation -> eventual canonical raw rebuild
```
