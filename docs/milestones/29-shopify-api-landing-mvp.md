# 29 - Shopify API Landing MVP

## Summary

This milestone added the first BigQuery landing path for Shopify Admin API data.

The goal was to write Shopify API-derived product and product variant data into isolated `raw_load` tables without replacing the existing CSV ingestion pipeline, modifying canonical `raw.shopify_*` tables, or changing downstream staging, marts, or analysis logic.

The milestone succeeded.

## What changed

Added a new Airflow DAG:

```text
dags/mm_shopify_api_products_landing_mvp.py
```

This DAG:

- starts a Shopify Bulk Operation for products and variants
- polls until the Bulk Operation completes
- downloads the JSONL result locally
- separates `Product` and `ProductVariant` records
- loads products into `raw_load.shopify_products_api_latest`
- loads product variants into `raw_load.shopify_product_variants_api_latest`
- validates the API landing tables
- writes a local landing summary

Added a validation query:

```text
sql/validation/shopify_api_products_landing_validation.sql
```

This query validates:

- API product landing row count
- API product variant landing row count
- duplicate product GraphQL IDs
- duplicate product variant GraphQL IDs
- missing variant parent product IDs
- orphaned variant parent product IDs
- basic SKU overlap with the existing CSV-derived product data

## Validation

Validated the DAG in Dockerized Airflow.

Loaded row counts:

```text
Product: 671
ProductVariant: 2436
```

Validated BigQuery landing tables:

```text
raw_load.shopify_products_api_latest
raw_load.shopify_product_variants_api_latest
```

The validation query returned expected results:

- product landing table populated
- variant landing table populated
- no duplicate product GraphQL IDs
- no duplicate variant GraphQL IDs
- no variants missing parent product IDs
- no orphaned variant parent product IDs

## Design decisions

The API landing path remains isolated.

This milestone intentionally does not:

- replace the Shopify CSV ingestion DAG
- modify canonical `raw.shopify_*` tables
- modify staging models
- modify marts models
- modify analysis models
- schedule API ingestion
- reconcile API-derived data into the business-facing warehouse

The existing CSV ingestion path remains the known-good fallback.

Current migration path:

```text
Shopify API -> isolated API landing tables -> API-vs-CSV comparison layer -> eventual canonical raw rebuild
```


This is the first API-derived BigQuery ingestion path in the project.
